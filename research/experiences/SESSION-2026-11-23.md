## Faits vérifiés
1. Le code historique comporte trois processus et trois fractales par processus, les neuf composantes sont obtenues via HMAC à partir de la même clé.
2. `use_fingerprint=False` par défaut ; le protocole ne démontre pas l'authenticité liée au contenu.
3. `verify` calcule une moyenne et un écart type sur six clés négatives, réunissant les blocs. La fusion par Stouffer n'est pas calibrée pour une interprétation en p-value ; aucune dépendance entre composantes n'est estimée.
4. Les résultats historiques du README reposent sur un signal synthétique ; ni test perceptuel, ni corpus représentatif dans le dépôt.
5. Le README pointe vers `README_fr.md`, `LICENSE` et `LICENSE-docs.md`, absents de l'inventaire racine effectivement lu lors de cette session ; vérifier la complétude de publication et ne pas reconstituer les licences de mémoire.

2. Ajouter une distribution de scores négatifs à partir de sources et clés indépendantes, calibrer hors test et publier les intervalles de confiance ; pas de cible de sécurité arbitraire.
3. Évaluer sur parole, musique et piano réels, avec tests d'écoute contrôlés.
4. Séparer robustesse à des dégradations bénignes et résistance à un adversaire adaptatif.
5. Tester la désynchronisation/alignement et la dérivation robuste du fingerprint avant de réclamer une résistance aux attaques de recopie.
